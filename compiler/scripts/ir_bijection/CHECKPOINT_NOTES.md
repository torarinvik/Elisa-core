# Checkpoint/resume qualification

Use the same explicit manifest and immutable inputs on every invocation:

    timeout 30s python3 ir_bijection.py left.ll right.ll --manifest renames.json --checkpoint proof.json --budget-seconds 4

Exit3 means INCOMPLETE: checked complete units saved, NO equivalence claim. Repeat the exact command. Exit0 prints equivalence only after simultaneous EOF and consumption of EVERY authorized manifest entry. Exit1 is a witnessed mismatch; exit2 is unsupported input/checkpoint/I/O. Keep the external30s cap; the internal deadline is cooperative at complete-function/module-line boundaries, not a hard process timeout. If externally killed mid-unit, only the earlier atomic checkpoint survives. No identical unit is skipped; both sides still run the ordinary classifier and full token/binding checks.

Every run hashes BOTH complete input files using bounded reads, recomputes named-type/internal-global indexes, and binds progress to exact resolved paths, sizes, hashes, canonical complete manifest (including producer/evidence fields and order), Python version, checker source SHA256 and index digest. A changed checker needs a new proof checkpoint from byte0; there is no rekey/force/rebase option. Manifest whitespace is not semantic; canonical decoded entries are the bound authority. Inputs changing during hashing/verification fail. Only functions/module lines are tokenized, not whole modules.

State contains separate byte offsets, next scope ordinal, next line number, unit count, all module-global/type forward AND reverse mappings (including unchanged names), all used authorizations, all changed mappings, completion bit and identity. Fresh runs validate persisted forward/reverse consistency, used/changed equality and authorization membership, offsets and actual complete-unit/scope/line boundaries before resuming. Local maps are released only after the complete function was checked. EOF rejects unused rows. Existing uncheckpointed verify_streams shares the EXACT same verify_unit implementation, so the proof loop is not weakened for batching.

Atomic publication writes a bounded checksummed JSON envelope to a temporary file, fsyncs it, then renames. Corrupt/mismatched/rekeyed identities fail closed; no automatic restart or overwrite on rejected checkpoint. State is LOCALLY TRUSTED proof-work bookkeeping with accidental-corruption checksums. It is NOT signed or tamper-proof against an actor able to rewrite the state and recompute its checksum. Such an actor could fabricate checked history. These files must never become untrusted compiler-cache authority, remotely supplied equivalence proofs or independently trusted evidence. Preserve checkpoint provenance and validation logs alongside inputs/manifest. This limitation is explicit rather than claiming an unhashed execution history is cryptographic proof.
